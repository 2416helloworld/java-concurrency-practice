# Q04 线程池参数调优实战（文档题）

## 场景

一个 Web 接口，平均响应时间 50ms，QPS 峰值 2000，任务是 CPU 密集 + 少量 IO。

## 要求（思考并写出结论，无需提交代码）

1. 估算核心线程数、最大线程数、队列容量，并说明理由。
2. 选择哪种拒绝策略？为什么？
3. 如何监控线程池的活跃线程数、队列积压、拒绝次数？

## 考察点

线程池参数估算、拒绝策略、监控。

## 参考要点

- CPU 密集：`N+1`（N=核数）；IO 密集：`2N` 或按 `N × (1 + 等待/计算)` 估算。
- 并发任务数 ≈ `QPS × 响应时间 = 2000 × 0.05 = 100`，据此定核心/最大线程与队列。
- 拒绝策略：`CallerRunsPolicy`（背压）或自定义（记录+降级），避免 `AbortPolicy` 直接抛异常。
- 监控：`getActiveCount()`、`getQueue().size()`、自定义 `RejectedExecutionHandler` 计数，或接 Micrometer。
